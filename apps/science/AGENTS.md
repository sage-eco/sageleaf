# Science App (`apps/science/`) — Agent Rules

**Package Name:** `@sageleaf/science`

## Overview

Nuxt 3-based data management frontend for the Sage platform. Focused on data analysis, visualization, and tools. **Desktop only** — no mobile targets.

## Framework & Architecture

Same stack as `apps/frontend/` (Nuxt 4.x, Vue 3, Apollo GraphQL, DaisyUI/Tailwind, Pinia) plus Tauri v2 for desktop packaging.

**Key difference from frontend:** Science is desktop-focused with an emphasis on data visualization. Its Tauri wrapper is desktop-only — no Android/iOS targets, no mobile plugins, no mobile capabilities file. That's intentional, not a gap. Refer to `apps/frontend/AGENTS.md` for shared patterns (Vue/Nuxt component structure, composables, GraphQL usage, routing, state management, styling, i18n).

## Project Structure

```
apps/science/
├── app/            # Nuxt app source (components, composables, pages, etc.)
├── config/         # Environment configs
├── gql/            # GraphQL queries/mutations (generated types)
├── i18n/           # Translation files
├── public/         # Public static files
└── src-tauri/      # Tauri desktop wrapper (Rust, no mobile targets)
```

## Internationalization

Follows the same patterns as `apps/frontend/` — see `apps/frontend/AGENTS.md`. Namespace is `science`. Always co-locate the namespace with the key:

```vue
<!-- template -->
<T ns="science" key-name="nav.dashboard" />

<!-- script -->
const { t } = useTranslate() t.value('nav.dashboard', { ns: 'science' })
```

**English (`en.json`) is the source of truth and may be edited directly** — update the matching key in the same diff. Other language files are managed by Tolgee; translators fill them in via the dashboard, so don't hand-edit them. Run `nx i18n science` to push English keys upstream and pull translated values back.

## Common Commands

```bash
# Development
nx dev science                    # Start dev server

# Build
nx build science                  # Build for production
nx generate science               # Generate static site (dev env)
nx generate:prod science          # Generate static (prod env)

# Desktop Development (Tauri)
nx desktop:dev science             # Start native desktop app with hot reload
nx desktop:build science           # Build release desktop bundle (macOS/Windows/Linux)

# GraphQL Code Generation (runs automatically as part of build)
nx build science                  # Also regenerates GQL types from schema

# Linting & Formatting
nx lint science                   # Lint with oxlint + ESLint, auto-fix
nx lint:ci science                # Lint for CI (no fixes, fail on warnings)
nx fmt science                    # Format code with oxfmt
nx fmt:ci science                 # Check formatting for CI
```

## GraphQL Types

After API schema changes, regenerate science types:

```bash
nx codegen:schema api             # Regenerate schema from code
nx build science                  # Regenerates GQL types as part of build
```

Note: `nx codegen science` does **not** exist — GQL types are regenerated by `nx build science`.

## Desktop Development (Tauri)

- Tauri provides a Rust-based native wrapper for macOS/Windows/Linux — no mobile targets, unlike `apps/frontend/`
- `src-tauri/` holds the Rust crate (`sageleaf-science`); it's registered in the root `Cargo.toml` workspace alongside `apps/frontend/src-tauri`
- Local desktop storage uses `tauri-plugin-sql` (SQLite); add migrations in `src-tauri/src/lib.rs` as science's local-storage needs grow
- Development uses hot reload with `nx desktop:dev science`; release bundles come from `nx desktop:build science`

**Tauri build errors:**

- Check Rust toolchain: `rustc --version`
- Check `src-tauri/Cargo.toml` for dependencies
- Review `src-tauri/tauri.conf.json` for config
- Common issues: missing permissions in `tauri.conf.json`, incorrect capabilities in `src-tauri/capabilities/default.json`
